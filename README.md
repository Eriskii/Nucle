# Nucle

A daily nuclear strike planning puzzle, played on a 1960s air defense console. Everyone
gets the same map, warheads, weather and objective each day. There's no backend: the
puzzle is generated from the date, and scores live in a cookie.

```sh
npm install
npm run dev
npm test                  # add NUCLE_DAYS=365 to audit a full year of puzzles
npm run build             # static site in build/
```

`?day=N` opens any puzzle number, unscored.

## How puzzles work

`src/lib/game/generator.ts` rolls a theatre, arsenal, weather, objective and conditions
from the day number, then a solver plays it. The solver's result sets the goal and par,
and proves the puzzle can be solved using only settings the console's controls can
produce. Rolls it can't solve are rerolled. `difficulty.ts` scores each puzzle by simulating
plausible but unoptimized players.

The daily board is simulated from the solver's par, since there's no server to hold real scores.

## Data

`static/data` is generated by `npm run data -- <source dir>`. The source dir needs:

- `pop/` and `built/`: [GHS-POP and GHS-BUILT-S R2023A](https://ghsl.jrc.ec.europa.eu/) at 30 arcseconds (European Commission JRC, CC BY 4.0)
- `places`, `lakes`, `rivers`, `roads`, `rail`, `urban` and `admin` as `.geojson`: [Natural Earth](https://www.naturalearthdata.com/) 10m (public domain)

Streets and buildings stream at runtime as vector tiles from [OpenFreeMap](https://openfreemap.org),
using the [OpenMapTiles](https://www.openmaptiles.org/) schema, with data © [OpenStreetMap](https://www.openstreetmap.org/copyright) contributors.
They're for display only. Scoring uses the population and built-up rasters.

Weapon effects are simplified from public figures in Glasstone & Dolan and OTA 1979. It's a game model, not a hydrocode.
